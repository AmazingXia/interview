# 项目排障与优化表达

## 1. 线上首屏变慢，你会怎么排查？

**参考答案：**
可以按“先定位、再归因、后优化、最后验证”回答：

1. 定位：看监控和日志，确认是全量还是局部用户
2. 归因：拆分 DNS、TCP、TTFB、资源下载、主线程阻塞
3. 优化：优先处理影响最大项（大资源、长任务、接口慢）
4. 验证：灰度发布，对比核心指标（如首屏时间、交互时间）

---

## 2. 如何描述一次 Webpack 优化案例？

**参考答案：**
用 STAR 结构：

- S：构建慢，影响开发效率
- T：在不影响功能前提下降低构建耗时
- A：缩小 loader 范围、配置 alias、拆分 vendors、开启缓存
- R：构建耗时下降，热更新速度提升，包体积更稳定

---

## 3. 微前端中样式冲突如何处理？

**参考答案：**
优先级建议：

1. 规范化命名（低成本）
2. 子应用容器前缀隔离（通用）
3. Shadow DOM（隔离更强，兼容成本更高）

面试时要强调“按成本和收益分层治理”，不是一上来就最重方案。

---

## 4. 缓存相关线上故障如何避免？

**参考答案：**

- 静态资源使用带内容指纹文件名（如 `contenthash`）
- HTML 设置短缓存或不缓存，保证入口可及时更新
- 版本发布做回滚预案，避免缓存与代码不一致
- 对关键资源增加校验和监控告警

---

## 5. 面试官问“你在性能优化中最有价值的一点”怎么答？

**参考答案：**
建议回答“建立了可量化闭环”：
不是只做点优化技巧，而是建立了“指标基线 -> 优化动作 -> 灰度验证 -> 复盘沉淀”的完整流程，确保优化能持续复用、可回归、可解释。
