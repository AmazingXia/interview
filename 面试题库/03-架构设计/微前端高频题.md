# 微前端高频题

## 1. 什么是微前端？适合什么场景？

**参考答案：**
微前端是把前端应用拆成多个可独立开发、独立部署、运行时集成的子应用。适合大型系统、多团队协作、历史系统迁移和多技术栈并存场景。

---

## 2. qiankun 的核心能力有哪些？

**参考答案：**

- 基于 single-spa 的应用生命周期管理（加载、挂载、卸载）
- HTML Entry 资源加载能力
- 样式隔离与 JS 沙箱隔离
- 子应用通信与运行时调度

---

## 3. 微前端如何实现路由切换和子应用切换？

**参考答案：**
典型实现会监听 `hashchange/popstate`，根据当前路由匹配 `activeRule`，然后按顺序执行：

1. 卸载旧子应用（`unmount`）
2. 首次进入时执行初始化（`bootstrap`）
3. 挂载新子应用（`mount`）

这和你当前手写框架中的 `register + route + lifecycle` 思路一致。

---

## 4. CSS 隔离有哪些方案？各自优缺点是什么？

**参考答案：**

- 命名空间/前缀：实现简单、兼容好，但需要约束样式规范
- Shadow DOM：隔离强，但对样式穿透和第三方库兼容要额外处理
- CSS-in-JS：组件级隔离好，但有运行时开销和团队习惯成本

---

## 5. JS 沙箱常见实现方式？

**参考答案：**

- Proxy 沙箱：为每个子应用代理 `window`，隔离全局变量改动
- 快照沙箱：挂载前拍快照，卸载时回滚
- iframe：隔离最强，但通信复杂、性能和体验成本高

面试可补充：现代浏览器优先 Proxy 沙箱，不支持 Proxy 时再降级快照沙箱。

---

## 6. 微前端的主要挑战有哪些？

**参考答案：**

- 公共依赖重复加载与版本冲突
- 跨应用通信复杂度提升
- 子应用样式和全局变量污染风险
- 首屏性能与资源调度变复杂
- 统一监控、鉴权、错误处理需要平台化设计
